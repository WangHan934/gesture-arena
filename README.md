# 空绘兽斗 · 怪兽 PvP

两位真人通过两台设备进入同一房间，选择怪兽、画符号施法，交替出招。

项目有**两个入口**：

| 页面 | 玩法 | 需要联网 | 需要对手 |
|---|---|---|---|
| `index.html`（默认） | 3D 怪兽 PvP | 是（同 Wi-Fi 或公网） | 是 |
| `classic.html` | 单机版：塔防制 / 1v1 决斗 | **否** | **否** |

单机版是演示兜底：网络不通、只有一台设备、或者对手没到时，直接开 `http://localhost:8000/classic.html`，
画手势召唤生物拆塔，或 1v1 走位对拼。两个页面顶部互相有跳转链接。

单机版和 PvP 用的是**同一套 3D 竞技场和同一批怪兽模型**（`assets/models/`），
只是玩法逻辑不同：PvP 是联网回合制施法，单机是本地即时战斗。
两套逻辑互不依赖 —— PvP 状态在服务端，单机状态全在浏览器里。

由提供的 `gesture-arena-2026-10-24.zip`（与仓库 a01bb3a 内容一致）、`c.html` 的六种施法规则和 Blender 美术资源整合。

## 运行

需要 **Node.js 20 或更高版本**，无需安装依赖。

```bash
npm start
```

也可在 macOS / Linux 执行 `bash start.sh`，Windows 双击 `start.bat`。
本机打开 `http://localhost:8000`。端口可用 `PORT=8080 npm start` 更改。

**只想单人试玩**：打开 `http://localhost:8000/classic.html`，不需要第二个人，也不需要联网对战。

**两台设备同一 Wi-Fi**：第二台设备打开服务端启动时显示的局域网地址，例如 `http://192.168.1.10:8000`。双方必须访问同一个服务端；把 localhost 链接发给其他设备无法连接。系统防火墙需允许该端口。

**两台设备跨网络**：将本项目运行在可公网访问的 Node.js 主机上，启动命令 `npm start`，使用主机提供的 `PORT`，并为外网入口配置 HTTPS。反向代理须关闭 SSE 缓冲。GitHub Pages 只托管静态页面，无法运行这个房间服务端。目前代码与交付包没有自动部署公网服务。

## 对战流程

1. 输入名字、选择怪兽，点击“创建对战房间”。
2. 另一台设备打开同一服务器地址，输入六位房间码，或打开邀请链接。
3. 双方锁定怪兽并准备，服务端随机决定先手。
4. 每次施法消耗一个回合，先打空对方生命获胜。每回合 45 秒，超时跳过；上限 120 回合，按剩余生命结算。
5. 双方点击“再战一局”即可重新选择怪兽。

| 符号 / 快捷键 | 技能 | 效果 | 冷却（己方回合） |
|---|---|---|---|
| ○ / 1 | 火球术 | 22 点伤害 | 0 |
| │ / 2 | 雷霆万钧 | 42 点伤害 | 2 |
| 2 / 3 | 治愈之光 | 回复 28 点生命，上限 140 | 1 |
| △ / 4 | 召唤援军 | 下一次伤害额外 +15 | 3 |
| □ / 5 | 护盾 | 下一次受到的伤害减半 | 2 |
| — / 6 | 终极奥义 | 70 点伤害 | 4 |

三只怪兽均为 140 HP、共享六种技能，外观自由选择。也可以直接点击技能按钮，方便触屏与现场演示。

## 摄像头画符号

点击“开启摄像头”后，只伸食指在空中画符号，停住 1.5 秒或放下手提交；下一笔前放下手复位。采用已有的本地 MediaPipe 模型，未开启时不申请摄像头。

浏览器的摄像头仅允许 `localhost` 或 HTTPS。手机访问普通局域网 HTTP 地址时，请使用触屏或按钮；需要手机摄像头则应通过 HTTPS 访问。物理摄像头与不同设备的识别精度仍需现场验证。

## 联网实现

- `server.mjs`：Node.js HTTP 服务、房间管理、单向实时事件流（SSE）。客户端通过 POST 提交操作。
- `src/pvp/engine.js`：服务端统一判定回合、技能伤害、冷却、超时和胜负。客户端提交的伤害值不会被采纳。
- `src/network/client.js`：房间连接、刷新恢复、自动重连。
- `src/input/gesture-recognizer.js`：独立的六种施法模板；保留旧识别接口供历史模块使用。
- `art/`：原始 Blender 模型、动画检查图、竞技场和怪兽预览、技术说明。

首页、大厅和对战均由本地 Three.js 加载真实 GLB 模型。`assets/models/fire.glb`、`shadow.glb`、`rock.glb` 和 `arena.glb` 均从提供的 Blender 原文件导出；没有替代模型，也不依赖外部 CDN。

炎角战魔包含 Idle / Walk / Run / Attack / Defend / Hit / Cast / Death 八个原有骨骼动作。对战按服务端事件播放攻击、施法、防御、受击、死亡，其余动作保留在 GLB 中。紫晶影魔与幽晶岩魔的源文件没有绑定与动作，显示原始静态网格。

3D 渲染使用 WebGL 2；加载失败会显示具体模型或初始化错误，不会静默替换成其他角色。手势与联网逻辑独立运行。导出脚本位于 `scripts/export_models.py`，原始 `.blend` 保存在 `art/blender/`。

模型、动画保留与路径检查包含在 `npm test` 中。

旧塔防、AI 决斗模块保留在源码中供参考，首页不再开放这些玩法。

## 验证

```bash
npm test
```

包含原有 159 项测试，以及 PvP 规则、六符号识别、空中轨迹提交和两个独立 HTTP 客户端的完整联网对局测试。浏览器手动核验覆盖双方入房、准备、技能施放和血量同步。

## 当前边界

房间在服务端内存中，重启会清空；玩家刷新页面可在原浏览器标签页恢复身份。断线时比赛时钟继续运行，超时照常跳过；主动离开比赛视为认输。空闲且双方离线的房间两小时后回收。邀请码是临时的，项目未添加账号、匹配排行或持久化数据库。


## 选怪界面

首页融合 `monster-arena.zip` 的图鉴、皮革/黄铜面板与铸铁舞台设计，中央使用本项目原始 GLB 怪兽和竞技场。点击图鉴或按 1–3 选怪，方向键也可切换；“召唤入场”打开建房/加入窗口，邀请链接会直接打开加入窗口。对战中的数字键仍为 1–6 技能。

详情中的生命、技能与冷却来自实际 PvP 规则；没有加入原演示的虚拟货币、购买怪兽或未实现的属性加成。三个原始怪兽、炎角战魔的八段原有动画及联网规则保持不变。
