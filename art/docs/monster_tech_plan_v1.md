# 《空绘兽斗》怪兽技术方案 v1

对应 Blender 文件：`AISummoner_Monsters_Arena_v2_FireAnim.blend`（Blender 5.2.3，30 fps，公制单位）。
本文所有数据均来自对该文件的实测，未经实测的内容会单独注明。

对象名与游戏角色名的对应关系：

| Blender 集合 / 前缀 | 游戏角色 | 定位 |
|---|---|---|
| `ShadowMonster_*` | 紫晶影魔 Amethyst Shadowfiend | 刺客 |
| `FireMonster_*` + `InfernalHornbeast_Rig` | 炎角战魔 Infernal Hornbeast | 战士 |
| `RockMonster_*` | 幽晶岩魔 Abyssal Crystal Golem | 坦克 |

## 一、模型结构检查结果

| 项目 | 炎角战魔 | 幽晶岩魔 | 紫晶影魔 |
|---|---|---|---|
| 部件对象数 | 12 | 11 | 11 |
| 顶点 / 三角面 | 5,568 / 10,112 | 3,748 / 6,652 | 3,567 / 6,382 |
| 身高（含角） | 2.92 m | 2.41 m | 2.61 m |
| 独立网格块（shell） | 256 | 211 | 188 |
| 非流形边 | 0 | 0 | 0 |
| UV 层 | 无 | 无 | 无 |
| 材质数 | 9 | 6 | 7 |
| 对象位置 | 原点 | X = +4.5 | X = −4.5 |
| 骨骼绑定 | 有（26 骨） | 无 | 无 |

结论如下。

面数对 PvP 场景很宽裕：同屏两只怪兽加竞技场合计约 3 万三角面，任何平台都没有压力。

网格是"拼装式"的。每个部件由多个闭合小块交叠组成，没有破面（非流形边为 0），渲染没有问题。但这种结构不适合用 Blender 的自动权重，也不利于做平滑形变。对低多边形的分段护甲风格来说，按部件硬绑定是可行的，炎角战魔现有绑定已经验证过这一点。

三只都没有 UV。纯色材质在 Unity 里可以直接用。如果要合批（见第六节）或烘焙光照贴图，必须补 UV。

材质偏多。导入 Unity 后，每个"网格 × 材质"组合就是一次绘制调用，导出前建议合并成一张调色板材质（见第六节）。

岩魔和影魔的偏移只在对象位置上，几何体本身以各自原点为中心，导出前把位置归零即可。

### 炎角战魔现有绑定（实测）

骨架为 `InfernalHornbeast_Rig`，骨骼数据名是 `InfernalHornbeast_Skeleton`，共 26 根骨骼，命名沿用 Unity Humanoid 规范：

- 躯干：Root、Hips、Spine、Chest、UpperChest、Neck、Head
- 手臂（左右各一套）：Shoulder、UpperArm、LowerArm、Hand
- 腿（左右各一套）：UpperLeg、LowerLeg、Foot、Toes
- 尾巴：Tail.01 – Tail.03

全部 12 个部件都以对象方式挂在骨架下，并带 Armature 修改器。所有顶点都有权重、权重已归一，没有漏绑。

存在的问题，按优先级排列：

1. **权重是硬绑定**：每个顶点只受 1 根骨骼影响。关节处靠球体体块遮挡，目前的动作里没有看到撕裂。但手肘或膝盖弯曲超过约 110° 时，可能出现穿插。
2. **Neck 骨骼没有绑定任何顶点**：脖子那段网格在 Body 部件里，权重给的是 UpperChest。大幅转头时，头和脖子之间可能出现缝隙。
3. **缺少下颌骨（Jaw）**：没法做张嘴咆哮或喷火。
4. **缺少爪骨**：三根爪不能单独张合。
5. **已有的 Attack、Idle、Walk 是逐帧烘焙的**：每个动作 260 条曲线，编辑起来不方便。Attack 也还没有打击帧标记。

## 二、绑定方案

骨架类型建议统一用 Unity 的 **Generic**，不用 Humanoid。原因有三：三只怪兽比例差异很大，各自有尾巴、下颌、反关节腿；每只都有专属动作，不需要跨角色重定向；Generic 能完整保留尾巴和下颌的动画。现有的 Humanoid 风格命名可以保留，Generic 下照样能用。

### 炎角战魔：在现有骨架上补强（不重做）

- 给 Neck 补权重：Body 里脖子那段网格的顶点，按高度在 UpperChest、Neck、Head 之间过渡分配。
- 给手肘、膝盖、腰部关节附近的顶点加 2 骨过渡权重，过渡区宽约 8 cm。可以写脚本按骨段距离自动计算，不改动其他区域。
- 新增 Jaw（父骨骼为 Head），把 Head 部件里下颌和下排牙齿的顶点改绑到 Jaw。
- 新增爪骨 Claw.L.1–3 和 Claw.R.1–3（父骨骼为 Hand），用于攻击时张爪。
- 尾巴从 3 节细分为 5 节，甩尾会更顺。这一项可选。

以上改动会修改现有绑定，所以需要你确认后再做。

### 幽晶岩魔：新建绑定

骨架与炎角战魔同构（Root → Hips → Spine → Chest → UpperChest → Neck → Head，四肢相同），差异如下：

- Shell（龟甲）整体硬绑到 Chest，不做形变，保证"坚固"的感觉。
- 尾巴 3 节，末端加 Tail.Club（岩锤），用于地裂震荡时砸地。
- 加 Jaw；手部加 Claw × 3，可选。
- 肩上的巨石护甲和晶簇硬绑到 UpperArm，晶簇可以另加 Crystal 骨骼，做护盾展开时发光、轻微伸缩。

### 紫晶影魔：新建绑定

- 腿是反关节的趾行腿，每条腿 4 节：UpperLeg → LowerLeg → Metatarsal（跗跖）→ Toes。Unity Generic 对此没有限制。
- 5 条影尾：先加一根 TailRoot，每条尾巴再接 3 节骨骼（TailA–E.01–03），共 16 根。
- 加 Jaw；手部加 Claw × 3，刺客的爪击很依赖爪子的动作。
- 暗影鬃毛：用 2–3 根辅助骨骼做整体飘动。或者不绑，在 Unity 里用 Shader 顶点动画做飘动，这样更省事。

### 权重方法（三只通用）

按部件硬绑定，加关节处 2 骨过渡。权重由脚本按"顶点到骨段的距离"计算，不使用 Blender 的自动权重（在拼装式网格上容易失败）。每个顶点最多 4 个影响，符合 Unity 默认的 Skin Weights 设置。

## 三、动画规划

### 炎角战魔：第一套基础战斗动画（已完成，30 fps，原地动作，不带根运动）

| 动作 | 帧 | 循环 | 来源 | 动作标记（事件） |
|---|---|---|---|---|
| Idle 待机 | 1–61 | 是 | 已有 | — |
| Walk 行走 | 1–41 | 是 | 已有 | — |
| Attack 普通攻击（烈焰重击） | 1–37 | 否 | 已有 | 待补：打击帧 |
| Run 奔跑 | 1–21 | 是 | 本次新增 | — |
| Defend 防御 | 1–31 | 7–31 循环 | 本次新增 | `Guard_Loop_Start` @7 |
| Hit 受击 | 1–19 | 否 | 本次新增 | `Hit_Impact` @3 |
| Cast 施法（火焰冲击） | 1–46 | 否 | 本次新增 | `VFX_FireBlast_Charge` @8，`VFX_FireBlast_Start` @16，`VFX_FireBlast_End` @30 |
| Death 死亡 | 1–76 | 否，停在末帧 | 本次新增 | `Collapse_Knees` @20，`Hit_Ground` @32，`VFX_Death_Fade` @40 |

新增动作的设计要点：

- **Run**：重型巨兽的冲刺。身体前倾约 20°，高抬膝，手臂与腿交替摆动，髋部和胸口反向扭转，尾巴抬起并左右甩动。
- **Defend**：双腿下蹲，前臂交叉护在面前，低头让巨角朝前当盾，呼应"炎角"的定位。第 7–31 帧可以循环，用来保持防御姿态。
- **Hit**：胸口中招，身体后仰，头被打偏，双臂甩开，尾巴上扬，第 19 帧回到起始姿势。
- **Cast**：第 1–10 帧后仰蓄力，双掌收到肩前；第 16 帧弓步前推，双掌朝前；第 16–30 帧保持喷火姿势；第 46 帧收回。对应手势是"手掌向前推动"。
- **Death**：先踉跄后仰，再双膝跪地，最后向前扑倒，第 38 帧有一次反弹，之后静止。

技术处理：

- 每个关键帧都给 26 根骨骼全部打上位置、旋转和缩放，和现有动作保持一致，避免 Unity 里切换动作时有骨骼残留上一个动作的姿势。
- Defend、Cast、Death 的腿部用两骨骼 IK 计算，两只脚都精确贴地，误差 ≤ 5 mm。
- 尾巴有防穿地检测，扎进地面就自动抬起。
- 每个动作的首帧都和静止姿势一致，切换时不会跳。
- 预览方法：骨架上有两条 NLA 轨道。已有的 `Preview_Idle_Walk_Attack` 占第 1–157 帧；新增的 `Preview_Run_Defend_Hit_Cast_Death` 占第 171–399 帧。把场景结束帧改为 399，就能连续播放全部 8 个动作。

## 四、技能特效设计

统一原则：每只怪兽一种主色，接近白色的高亮核心加饱和的外缘，低多边形碎片形状（三角面片、晶体），不用写实的烟雾序列帧，和模型风格保持一致。特效在 Unity 里用 URP 的 Particle System 或 VFX Graph 实现，由动画事件触发（对应上表中的动作标记）。

| 技能 | 形态 | 颜色 | 触发 / 判定 |
|---|---|---|---|
| 烈焰重击 | 爪尖拖出 3 道弧形火焰拖尾；命中时爆出橙色火星和地面焦痕 | 橙 #FF5A10，核心 #FFC060 | 打击帧生成拖尾；扇形判定 90° × 2.5 m |
| 火焰冲击 | 双掌前方的扇形火焰流：低多边形火舌面片沿扇形扩散，再叠加热浪扭曲 | 同上 | `VFX_FireBlast_Start` 到 `_End` 期间持续判定；扇形 60° × 6 m |
| 炎角冲锋 | 角尖燃起火焰，身后拖火焰轨迹；撞击时冲击环加震屏 | 同上 | 冲刺期间胶囊判定 |
| 炼狱爆发 | 全身鬃毛火焰放大到 2 倍；以脚下为圆心向外扩散的火环，地面熔岩裂纹贴花 | 橙到深红 | 圆形 5 m，分 3 段伤害 |
| 暗影爪击 | 紫色半透明的爪痕切线，停留 0.15 s 后消散 | 紫 #9A40FF，核心 #E0C0FF | 打击帧 |
| 影袭突进 | 身体半透明加残影（2–3 个半透明复制体）；终点爆出暗影碎片 | 紫到黑 | 位移路径判定 |
| 紫晶飞刺 | 从背刺位置射出 5 枚低多边形紫晶棱柱，带拖尾，命中后碎裂 | 紫 | 投射物 |
| 暗影裂界 | 地面展开黑紫色裂隙贴花，半径 4 m；怪兽从裂隙中连续闪现突袭 | 黑紫 | 区域内每 0.5 s 判定一次 |
| 岩拳重击 | 命中点溅射碎石块（低多边形），伴随尘土环 | 灰加青绿高光 | 打击帧 |
| 晶石护盾 | 六边形蜂窝能量罩（呼应龟甲的六边形纹），受击处的格子闪亮 | 青绿 #30FFB0 | 减伤状态 |
| 地裂震荡 | 从双拳落点向前放射 3 道地裂，裂缝里冒出青绿光；沿途地面石块抬起 | 青绿 | 直线 8 m × 1.5 m |
| 晶核风暴 | 胸口晶核爆亮，环绕身体旋转飞出晶体碎片，并扩散 | 青绿 | 圆形 6 m |

通用特效还有四类：

- **召唤**：从出生点法阵升起光柱，怪兽由下往上溶解显现。
- **受击闪白**：在 Shader 里加 0.08 s 的自发光闪烁。
- **护盾破碎**：六边形格子炸散。
- **死亡**：在 `VFX_Death_Fade` 时机，身体从脚到头溶解成该元素的粒子。

观战大屏的可读性要求：技能特效的核心亮度要明显高于场景火盆，后处理 Bloom 只让自发光部分泛光。双方血条用世界空间的 UI，挂在头顶上方 0.4 m。

## 五、竞技场：现状与"远古元素斗兽场"要求的差距

| 要求 | 现状（`Arena` 集合） | 调整 |
|---|---|---|
| 大型圆形或八边形战斗区 | 圆形，半径 11 m，低多边形石板 | 保持 |
| 低多边形石块、破损石柱、遗迹 | 有城墙、看台、8 根完整的火盆柱、悬崖 | 把 3–4 根柱子改成断柱和倒塌的残块，加入散落的石块 |
| 地面大型魔法符文 | 中央八卦封印加符文环 | 加一道连接两个法阵的外圈符文带 |
| 两端怪兽召唤法阵 | 南北各有一个出生点光圈（`Arena_Spawn_A/B`） | 放大到半径 2 m，改成元素色（随召唤的怪兽变色），加召唤光柱 |
| 紫、橙、青绿晶体点缀 | 只有旗帜是这三色 | 在墙根和断柱旁加三色晶簇，每色 3 组，复用怪兽的晶体网格 |
| 东方雕刻 + 西方建筑 | 中式四柱三间牌坊，西式城墙、城垛、看台 | 在墙面加《山海经》异兽浮雕板（低多边形浮雕） |
| 中央宽敞、不挡视线 | 对战相机前方的 2 根柱子会遮挡一点边缘 | 把南侧两根柱子外移到墙根，或者改成断柱 |
| 第三人称观战 | 有 `Arena_Camera_Battle`（固定机位） | 改为跟随双方中点的动态机位（见下） |

观战相机建议：

- 目标点取双方怪兽的中点，抬高到 1.4 m。
- 相机距离 = clamp(双方间距 × 1.1 + 6 m, 9 m, 16 m)，俯角 18–25°，FOV 40°。
- 让两只怪兽的完整身体（最高 2.9 m，加上头顶血条）始终留在画面中间 70% 的区域里。

另外，`Monster_Presentation` 里的三盏展示灯（照亮中央的光斑就是它们造成的）只用于模型展示，进游戏时不要导出。

## 六、Blender 到 Unity 的导出流程

**1. 每只怪兽单独导出一个 FBX。** 把该怪兽的部件复制到导出用集合里，按 Ctrl+J 合并成一个网格。合并时同名的顶点组会自动合并，权重保留；材质槽也合并，同名材质会去重。

**2. 归零。** 骨架和合并后的网格都放到原点（岩魔、影魔现在偏移 ±4.5 m），然后应用旋转和缩放。

**3. 合并材质（推荐）。** 补一套 UV，把每种材质的面映射到一张 256×256 调色板贴图的对应色块上，同时生成一张自发光贴图。这样每只怪兽只用 1 个 URP Lit 材质，也就是 1 次绘制调用。如果暂时不做，也可以保留多材质直接导出，功能上没有区别。

**4. FBX 导出设置：**

- Selected Objects，对象类型选 Armature + Mesh
- Apply Scalings：FBX All，Forward：−Z，Up：Y，勾选 Apply Unit
- Armature：取消 Add Leaf Bones，勾选 Only Deform Bones
- Bake Animation：开启，勾选 All Actions，取消 NLA Strips，Simplify 设为 0
- 每个动作会成为一个独立的 Take

**5. 动作标记的处理。** FBX 不会导出 Pose Marker。我会写一个脚本，把所有动作的标记导成一个 JSON 文件（动作名 → 事件名 → 帧号、秒数）。Unity 侧用一个导入后处理脚本（AssetPostprocessor），按这个 JSON 自动给动画片段添加 Animation Event。

**6. Unity 导入设置：**

- Rig 选 Generic，Root node 设为 Root
- Animation 中，Idle、Walk、Run 勾选 Loop Time；Defend 的循环区间是 7–31 帧，可以拆成 Defend_Enter 和 Defend_Loop 两个片段
- 原地动作，Apply Root Motion 关闭，移动交给角色控制器
- 材质用 URP Lit，在 Emission 上叠加 HDR 颜色，后处理 Volume 里开 Bloom

**7. 朝向验证（未经实测，需要确认）。** 怪兽在 Blender 里面朝 −Y。按上面的设置导出后，在 Unity 里应该面朝 +Z，但我还没有用 Unity 实际验证过。首次导入时请确认；如果朝向反了，在 Unity 的模型导入设置里调整，不要回 Blender 里转模型。

2. 确认是否允许修改炎角战魔的现有绑定（补 Neck 权重、关节过渡、下颌骨、爪骨），然后给 Attack 补打击帧标记。
3. 给幽晶岩魔和紫晶影魔建立绑定，并做基础八件套动画。
4. 按第五节调整竞技场。
5. 先导出炎角战魔做一次 Unity 导入测试，验证朝向、动画和事件，再批量导出另外两只。
